**End-of-day source review, QC plans in chat, new Source QC and Finance screens, passive capture (Experimental), and more reliable uploads**

{/* truncate */}

### Source QC

- **End of day** - in the Chrome side panel, open the study's subject list in eClinPro and click **Run end of day**. Navigator reads the visits completed in the last 30 days and skips visits that the study already holds. When the run ends, Navigator sends an email report that lists what to review first. A site needs a portal set up for end of day.
- **End-of-day runs tab** - **Source Quality Control** has an **End-of-day runs** tab. Open a run for its report and a visit for its full result. A site with no portal does not show the tab.
- **Capture the screen and every PDF** - the side panel can capture the screen and all PDFs on a page in one step.
- **New side panel layout** - the **Source QC** screen in the side panel has a new layout. **End of day** is a separate action from the capture.
- **Findings by visit** - the **Patients** page groups the Source QC findings of a patient by visit and counts the open ones.
- **Fewer false findings** - Source QC reads across page breaks in long eSource printouts. It no longer reports findings about form text, absent fields, or not-done dates.
- **Latest EDC cross-check** - each user keeps their own latest EDC cross-check on a Source QC document. A re-run that fails keeps the last good result.

### Chat

- **QC plan** - ask chat for a QC plan, for example "Create a QC plan for the screening visit". Navigator builds a table from the protocol and the Schedule of Assessments. A plan for many visits starts with a timeline. Ask chat to compare the source documents against the protocol to get findings with a suggested query for each one.
- **Check the current screen against billing rules** - ask chat to check the screen that you see against the billing rules of the study.
- **Answers at full width** - chat answers use the full width of the page and end with a line that names their sources. A long list of document types collapses into one pop-up.
- **Clearer filter messages** - when a document type filter hides documents from chat, the answer says so.
- **Stop works sooner** - the stop icon also ends a run that you stop before the answer starts, or after an approval pause.

### Finance and passive capture

- **Finance desk** - the **Finance** desk is a patient queue for the active study. Chat tools for reconciliation are removed. Finance chat skills follow user roles.
- **Passive capture (Experimental)** - the side panel can save pages on the addresses that a study allows. Every 3 hours, Navigator reads the saved pages and finds billable items. The **Finance** desk shows them with a link to the study and the page as evidence. A user turns passive capture off in the **Capture** tab. A site administrator can turn it off for a study in **Collection Settings**. The privacy policy and the terms describe passive capture. See [Passive capture](/extension/passive-capture).

### Documents and uploads

- **Uploads end in a short time** - an upload job that never finishes now ends as failed, and you can try again. Navigator retries short outages by itself.
- **Failed pages show as failed** - a document with pages that Navigator could not read shows as failed, not as complete.
- **Warning before you leave** - Navigator warns you before you leave the page while any upload runs.
- **No partial files** - a failed upload leaves no temporary file and no stored file.
- **No duplicate current versions** - two uploads of the same file cannot both become the current version.
- **Access lists on every version** - a document access list applies to all versions of the document. A site keeps its restriction when a sponsor publishes an amendment.
- **Sponsor staging** - each sponsor has its own staging collection. A sponsor-locked collection cannot be renamed or deleted.
- **Study delete** - when an administrator deletes a study, Navigator also removes its document files and study data.
- **Spreadsheet downloads** - cell text stays as you typed it in Excel, PDF, and Word downloads. PDF download works for spreadsheets with many wide columns.

### Security and access

- **Expired password by email link** - a user with an expired password who signs in with an email link must choose a new password. A reset by an administrator no longer shows the expired-password note.
- **Trusted devices** - each account keeps its own trusted-device cookie on a shared browser.
- **Wrong attempts** - Navigator counts password confirmations and turn-off codes before it checks them. A rejected sign-in no longer uses up a backup code.
- **Web security** - the app script policy no longer uses `unsafe-inline`. The API sends the CORS credentials header only to allowed origins. The app domain publishes a `security.txt` file.
- **Personal documents** - other users' personal documents do not show in the chat source picker.

### Platform

- **Python 3.12** - the backend runs on Python 3.12.
- **Safer releases** - each new production revision gets a smoke test before it takes traffic.
